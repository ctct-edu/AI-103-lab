# ナレッジ マイニング ソリューションの作成

この演習では、Azure AI Search を使用して、旅行パンフレットのドキュメント セットにインデックスを付けるナレッジ マイニング ソリューションを作成します。インデックス作成の処理では AI スキルを使用してドキュメントから重要な情報を抽出します。そして、インデックスを検索する Python クライアント アプリケーションを作成します。

この演習の所要時間は約 **40** 分です。

## 前提条件

- Visual Studio Code、Python 3.13 以降（演習環境にはインストール済みです）

> **注意**: この演習は、演習 01〜05 で使用する共用の Foundry プロジェクトを使わない **独立した演習** です。専用の Azure AI Search リソースとストレージ アカウントが必要です。ただし、この演習の「クリーンアップ」では、1〜4 日目で共用してきたすべてのリソースを、まとめて削除します。

## Azure リソースの作成

このソリューションには、Azure サブスクリプションに複数のリソースが必要です。すべて同じリージョンに作成します。

### Azure AI Search リソースの作成

1. Web ブラウザーで [Azure ポータル](https://portal.azure.com)（`https://portal.azure.com`）を開き、Azure の資格情報でサインインします。

1. **&#65291;リソースの作成** ボタンを選択し、`Azure AI Search` を検索して、次の設定で **Azure AI Search** リソースを作成します。
    - **サブスクリプション**: *自分の Azure サブスクリプション*
    - **リソース グループ**: 各自に割り当てられた既存のリソース グループ（**AI103StudentXX**）を選択します。
    - **サービス名**: `ai103searchXXYYYYMMDD`（XX は自分の番号、YYYYMMDD は当日の日付。小文字と数字のみ。例:ai103search0020261127）
    - **場所**: **East US 2**（推奨）
    - **価格レベル**: **[価格レベルの変更]** を選択し、**[価格レベルの選択]** で **基本**（Basic）を選んで **[Select]** を選択します（既定は Standard）。

    ![[検索サービスを作成する] のスクリーンショット。青枠は [リソース グループ]、[サービス名]、[場所]、赤枠は [価格レベル] の 基本 と [確認して作成] ボタン。画面は East US 2 を選んだ例。](../Media/d4e06-01-create-search-service.png)

    ![[価格レベルの選択] のスクリーンショット。赤枠は 基本（Basic）の行と [Select] ボタン。](../Media/d4e06-02-search-pricing-basic.png)

    > **注意**: East US 2 で「InsufficientResourcesAvailable」（リージョンのリソース不足）のエラーでデプロイが失敗した場合は、**[場所]** を **East US** にして作成し直してください。その場合、次のストレージ アカウントも **East US** に作成します。

    > **注意**: Basic レベルは時間単位で課金され、リソースを削除するまで課金が続きます。演習が終わったら、必ず最後の「クリーンアップ」でリソース グループごと削除してください。

1. デプロイが完了するまで待ってから、デプロイされたリソースに移動します。

1. **[概要]**（Overview）ページを確認します。ここでは、ビジュアル インターフェイスを使用して、検索ソリューションのさまざまなコンポーネントの作成、テスト、管理、監視ができます。

    ![Azure AI Search の [概要] ページのスクリーンショット。赤枠は [データのインポート]、[場所]、[価格レベル] の 基本。](../Media/d4e06-03-search-overview.png)

### ストレージ アカウントの作成

1. Azure ポータルのホーム ページに戻り、次の設定で **ストレージ アカウント** リソースを作成します。
    - **サブスクリプション**: *自分の Azure サブスクリプション*
    - **リソース グループ**: *Azure AI Search リソースと同じリソース グループ*
    - **ストレージ アカウント名**: `ai103kmstgXXYYYYMMDD`（小文字と数字のみ。例：ai103kmstg0020261127）
    - **リージョン**: *Azure AI Search リソースと同じリージョン*
    - **主要サービス**: Azure Blob Storage または Azure Data Lake Storage Gen 2
    - **パフォーマンス**: Standard
    - **冗長性**: ローカル冗長ストレージ (LRS)（既定は GRS のため、変更します）

1. デプロイが完了するまで待ってから、デプロイされたリソースに移動します。

## ドキュメントの Azure Storage へのアップロード

ナレッジ マイニング ソリューションは、Azure Blob Storage に保存された旅行パンフレットのドキュメントから情報を抽出します。

1. 演習環境に配置済みの `Labfiles/06-knowledge-mining/documents` フォルダーを開き、旅行パンフレットの PDF ファイル（6 つ）があることを確認します。

1. Azure ポータルで、ストレージ アカウントに移動し、ナビゲーション ペインで **[ストレージ ブラウザー]**（Storage browser）を選択します。

1. ストレージ ブラウザーで、**[BLOB コンテナー]**（Blob containers）を選択します。

1. ツール バーで **[+ コンテナー]** を選択し、次の設定で新しいコンテナーを作成します。
    - **名前**: `documents`
    - **匿名アクセス レベル**: プライベート (匿名アクセスなし)

1. **documents** コンテナーを選択し、ツール バーの **[アップロード]** ボタンを使用して、`documents` フォルダーの .pdf ファイルをアップロードします。

## インデクサーの作成と実行

AI スキルを使用してドキュメントから情報を抽出するインデクサーを作成します。

1. Azure ポータルで、Azure AI Search リソースに移動します。その **[概要]** ページで、**[データのインポート]**（Import data）を選択します。

1. **[データに接続する]**（Connect to your data）ページの **データ ソース**（Data Source）の一覧で、**Azure Blob Storage** を選択します。

1. **[キーワード検索]**（keyword search）を選択します。

1. **データに接続する** フォームで、次の設定を行います。
    - **ストレージ アカウント**: *先ほど作成したストレージ アカウント*
    - **BLOB コンテナー**: **documents** コンテナーを選択します。
    - **Access control** の **Enable document-level permissions**（ドキュメント レベルのアクセス許可を有効にする）の**チェックを外します**。

        > **重要**: 新しいポータルでは、このチェックボックスが既定でオンになっています。オンのままインデックスを作成すると、検索時にユーザーのアクセス許可で結果が絞り込まれます。この演習のドキュメントにはアクセス許可の情報がないため、検索エクスプローラーでも Python アプリでも結果が **0 件**になります。必ずチェックを外してから先に進んでください。

    - 残りのオプションは既定値のままにして、**[次へ]**（Next）を選択します。

1. **[AI エンリッチメントを適用する]**（Apply AI enrichments）で、次の設定を行います。
    - **[フレーズの抽出]**（Extract phrases）を選択します。
    - **[エンティティの抽出]**（Extract entities）を選択し、設定アイコンを選択して、**[人物]**（Persons）と **[場所]**（Locations）のみが選択されていることを確認してから、**[保存]** を選択します。
    - **[画像からのテキストの抽出]**（Extract text from images）を選択し、設定アイコンを選択して、**[タグの生成]**（Generate tags）と **[コンテンツの分類]**（Categorize content）が選択されていることを確認してから、**[保存]** を選択します。
    - まだ選択されていない場合は、無料の Foundry Tools リソース オプションを選択し、**[次へ]** を選択します。

    > **注意**: Azure AI Search の無料の Azure AI Services エンリッチメントを使用してインデックスを付けられるドキュメントは、最大 20 件です。運用ソリューションでは、Azure AI Services リソースを作成してアタッチする必要があります。

1. **[マッピングのプレビュー]**（Preview mappings）で、次の構成を設定します。
    - 前の手順で選択したオプションに基づいて、フィールドはすでにマップされています。
    - 次のフィールドを確認し、次の表のとおりに構成されていることを確認します。フィールドを更新するには、フィールドを選択して **[フィールドの構成]**（Configure field）を選択します。その他のフィールドは、既定の設定のままにします。

    | ターゲット インデックスのフィールド名 | 取得可能 | フィルター可能 | 並べ替え可能 | ファセット可能 | 検索可能 |
    | ---------- | ----------- | ---------- | -------- | --------- | ---------- |
    | metadata_storage_size | &#10004; | &#10004; | &#10004; | | |
    | metadata_storage_last_modified | &#10004; | &#10004; | &#10004; | | |
    | title | &#10004; | &#10004; | &#10004; | | &#10004; |
    | locations | &#10004; | &#10004; | | | &#10004; |
    | persons | &#10004; | &#10004; | | | &#10004; |
    | keyPhrases | &#10004; | &#10004; | | | &#10004; |

    - **[次へ]** を選択します。

1. **[詳細設定]**（Advanced settings）で、次の設定を行います。
    - **[セマンティック ランカーを有効にする]**（Enable semantic ranker）が選択されていることを確認します。
    - まだ選択されていない場合は、**スケジュール**（Schedule）を **[1 回]**（Once）に設定します。
    - **[次へ]** を選択します。

1. **[確認と作成]**（Review and create）で、**オブジェクト名のプレフィックス**（Objects name prefix）を `margies-index` に設定し、**[作成]** を選択します。

1. 左側のナビゲーション ペインの **[検索管理]**（Search management）の下で、**[インデクサー]**（Indexers）ページを表示します。**margies-index-indexer** が表示されるはずです。数分待ち、**[更新]**（Refresh）を選択して、**ステータス**が **[成功]**（Success）になるまで繰り返します。

## インデックスの検索

1. Azure AI Search リソースの左側のナビゲーション ペインで、**[検索管理]**（Search management）の下の **[インデックス]**（Indexes）を選択し、**margies-index** を選択します。インデックスの画面が開いたら、**[検索エクスプローラー]**（Search explorer）タブを選択します。

    > **注意**: ポータルのバージョンによっては、リソースの **[概要]** ページのツール バーにも **[検索エクスプローラー]** が表示されます。表示されない場合は、上記のとおりインデックスの画面から開いてください。

    > **注意**: 検索エクスプローラー上部に「このインデックスでは、アクセス許可に基づく結果フィルター処理が使用されます」というメッセージや **[サインインしているユーザー として クエリを実行する]** のドロップダウンが表示される場合は、インデックス作成時に **Enable document-level permissions** をオフにし忘れています。この状態では結果が 0 件になるため、「インデクサーの作成と実行」の手順で、チェックを外してインデックスとインデクサーを作り直してください。

1. 検索エクスプローラーの **クエリ文字列**（Query string）ボックスに `*`（アスタリスク 1 つ）と入力して、**[検索]**（Search）を選択します。

    このクエリは、インデックス内のすべてのドキュメントを JSON 形式で取得します。各ドキュメントのフィールドには、ドキュメントの内容、メタデータ、および認知スキルによって抽出されたエンリッチされたデータが含まれています。

1. **[表示]**（View）メニューで **[JSON ビュー]**（JSON view）を選択し、検索の JSON 要求が表示されていることを確認します。

    ```json
    {
      "search": "*",
      "count": true
    }
    ```

1. 結果の上部にある **@odata.count** フィールドは、検索で返されたドキュメントの数を示します。

1. JSON 要求を変更して、**select** パラメーターを含めます。

    ```json
    {
      "search": "*",
      "count": true,
      "select": "title,locations"
    }
    ```

    今回は、結果にファイル名と、ドキュメントの内容で言及されている場所のみが含まれます。ファイル名は **title** フィールドにあります。**locations** フィールドは、AI スキルによって生成されたものです。

1. 次のクエリ文字列を試します。

    ```json
    {
      "search": "New York",
      "count": true,
      "select": "title,keyPhrases"
    }
    ```

    この検索は、検索可能な任意のフィールドで "New York" に言及しているドキュメントを検索し、ファイル名とキー フレーズを返します。

1. もう 1 つクエリを試します。

    ```json
    {
        "search": "New York",
        "count": true,
        "select": "title,keyPhrases",
        "filter": "metadata_storage_size lt 380000"
    }
    ```

    これは、"New York" に言及している、380,000 バイトより小さいドキュメントを返します。

## 検索クライアント アプリケーションの作成

Azure AI Search SDK を使用して、Python クライアント アプリケーションからインデックスにクエリを実行します。

### 検索リソースのエンドポイントとキーの取得

1. Azure ポータルで、Azure AI Search リソースの **[概要]** ページに戻ります。**Url** の値（例: `https://{リソース名}.search.windows.net`）を確認します。これが検索リソースのエンドポイントです。

1. 左側のナビゲーション ペインで **[設定]** を展開し、**[キー]**（Keys）ページを表示します。**クエリ** キーを確認します。クライアント アプリケーションで必要になります。

    > **注意**: Azure AI Search は、サービスごとに 1 つの既定のクエリ キーを作成します。Azure ポータルでは、この既定のクエリ キーの名前が空白で表示されることがあります。これは想定された動作です。

### Azure AI Search SDK を使用する準備

アプリケーションの初期ファイルは、演習環境に配置済みです。

1. **Visual Studio Code** を開き、**[ファイル] > [フォルダーを開く]** を選択して、配置済みの `Labfiles/06-knowledge-mining` フォルダーを開きます。

1. VS Code のエクスプローラー ペインで **Python** フォルダーを展開し、**Python** フォルダーを右クリックして、**[統合ターミナルで開く]** を選択します。

1. ターミナルで次のコマンドを入力して、演習用にあらかじめ構築済みの仮想環境 (`labenv`) を有効化します。

    ```
    .\labenv\Scripts\Activate.ps1
    ```

    > **注意**: 必要な Python パッケージは `labenv` に事前インストール済みです。`pip install` を再実行する必要はありません。requirements.txt により、[azure-search-documents](https://learn.microsoft.com/python/api/overview/azure/search-documents-readme?view=azure-python) Python SDK パッケージとその依存関係がインストール済みです。

1. VS Code のエクスプローラー ペインで、**Python** フォルダーの **.env** ファイルを開きます。

1. 次のプレースホルダーの値を置き換えます。
    - **your_search_endpoint**: *Azure AI Search リソースのエンドポイント*
    - **your_query_key**: *Azure AI Search リソースのクエリ キー*
    - **your_index_name**: *インデックスの名前*（`margies-index` になっているはずです）

    > **注意**: クエリ キーは秘密情報です。**.env** 以外のファイルに貼り付けたり、他の人と共有したりしないでください。

1. ファイルを保存します（**Ctrl+S**）。

1. VS Code で、**search-app.py** ファイルを開きます。

1. コードを確認します。このコードは、次のことを行います。
    - .env ファイルから構成設定を取得する。
    - エンドポイント、キー、インデックス名で `SearchClient` を作成する。
    - ユーザーに検索クエリの入力を繰り返し求める（"quit" と入力するまで）。
    - クエリを使用して、タイトル順に並べ替えた次のフィールドを返すインデックスの検索を行う。
        - title
        - locations
        - persons
        - keyPhrases
    - 返された検索結果を解析して、結果セットの各ドキュメントについて返されたフィールドを表示する。

    > **ヒント**: この演習の search-app.py は、追加するコードのない完成したコードです。プログラムの流れを読んで確認します。

1. VS Code のターミナルで、アプリケーションを実行します。

    ```
    python search-app.py
    ```

1. プロンプトが表示されたら、`London` のようなクエリを入力して、結果を確認します。

1. `flights` など、別のクエリも試します。

1. テストが終わったら、`quit` と入力してアプリを閉じます。
